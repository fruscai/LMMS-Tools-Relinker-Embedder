LMMS Path Relinker

Repair broken sample paths across hundreds of projects at once

Runs entirely in your browser
About

This tool processes files locally in your browser and does not upload anything. It repairs LMMS projects whose samples stopped loading after a move to another machine or folder. By default it points every sample at your LMMS gig folder, using the usergig: reference that LMMS resolves through its own gig directory setting.

How to start
  1. Copy your audio files into your LMMS gig folder. On every system this is the gig folder inside your LMMS user samples directory, for example Documents/lmms/samples/gig.
  2. Drag a folder or ZIP of projects into the drop zone below, or use the Choose ZIP, Choose folder or Choose projects buttons. Every .mmp and .mmpz inside is found, at any depth.
  3. Leave Point everything at my gig folder ticked. Every sample that is not one of LMMS's own becomes usergig:<file name>, with no paths to type. Samples that already carry a working reference, such as local: or factorysample:, are left alone.
  4. If two different samples share a file name, the tool stops and lists them, because both would end up pointing at whichever file reached the gig folder last. Use the button it offers to keep the parent folder, or rename the files.
  5. If you need a different destination instead, untick that box and type the broken root path into the first field and the correct one into the second. The before and after lines underneath show the change applied to a real reference from your own project.
  6. Click the Scan button. This is a preview only, and nothing is modified. The table shows which projects contain the path and how many references will change.
  7. Click the Repair & download button. Your original files are never touched. The ZIP that downloads holds the repaired projects plus a repair log in JSON and CSV.
  8. Check your work. Open the repaired projects in LMMS and make sure every file loads with no missing sample warnings.
